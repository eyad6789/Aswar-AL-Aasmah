## Summary
This is a clean, dependency-free static marketing site, but it ships with a runtime-breaking JavaScript bug: `js/main.js` attaches a submit handler to a `contactForm` element that no longer exists in `index.html`, throwing a TypeError that silently kills the language switcher and smooth-scroll features for every visitor. The contact section was reduced to a decorative image, so users have no working contact form at all. Secondary issues are hardening (missing CSP/Referrer-Policy, deprecated header, soft-404), repo hygiene (no .gitignore, fileMode noise), and minor performance (unreferenced 244 KB logo, no image lazy-loading, unthrottled scroll handler). Overall grade: C

## High

### [H1] Missing `contactForm` element crashes main.js and breaks language switcher + smooth scroll
- Where: js/main.js:137 (references `getElementById('contactForm')`); index.html:462-464 (contact section is just `<img src="assets/unnamed.jpg">`, no `<form>`)
- Evidence: `grep '<form\|contactForm' index.html` returns nothing; `document.getElementById('contactForm').addEventListener('submit', ...)` runs unguarded at top level.
- Impact: `getElementById('contactForm')` returns null, so `.addEventListener` throws `TypeError: Cannot read properties of null`. This is a synchronous top-level throw, so everything defined after it never runs: the smooth-scroll anchor handler (lines 165-175) and the entire `DOMContentLoaded` block that wires up the language switcher and applies translations (lines 206-222). The AR/EN toggle and in-page smooth scrolling are dead in production.
- Fix: Either restore the contact `<form id="contactForm">...</form>` markup in index.html (the README still documents wiring it to Formspree), or guard the handler: `const form = document.getElementById('contactForm'); if (form) form.addEventListener('submit', ...)`. Verify the language switcher works after the fix.

### [H2] No functioning contact form for visitors
- Where: index.html:462-464 (contact-form-wrapper holds only an image)
- Evidence: The contact section renders `assets/unnamed.jpg` where a form is expected; README Step 4 still describes a `contactForm` to wire up that is absent from the current markup.
- Impact: Prospective customers on this lead-generation site cannot send an inquiry through the page. Only the WhatsApp float, `tel:`, and `mailto:` links work. Combined with H1, the JS that would have animated a submit also crashes. For a marketing site this is a direct loss of leads.
- Fix: Add a real contact form (name/email/message inputs with `required` and `type="email"`) and point its `action` at a backend such as Formspree/EmailJS per README, or remove the JS form handler entirely and rely on the documented WhatsApp/email channels.

## Medium

### [M1] Unguarded DOM lookups throughout main.js
- Where: js/main.js:16-25 (navbar, backToTop inside scroll handler), 31 (navToggle), 69 (backToTop click)
- Evidence: `navbar.classList.toggle(...)` and `getElementById('backToTop').classList.toggle(...)` run on every scroll event with no null checks; `navToggle.addEventListener(...)` is unguarded.
- Impact: Any future markup change that removes or renames one of these IDs reintroduces the same class of crash as H1, on a hot path (scroll). Brittle and hard to debug.
- Fix: Cache elements once and guard each access, e.g. early-return if `!navbar`. Consider a single `const el = id => document.getElementById(id)` helper with null checks.

### [M2] Missing security headers in .htaccess (no CSP, no Referrer-Policy; deprecated X-XSS-Protection)
- Where: .htaccess:17-22
- Evidence: Headers block sets only `X-Content-Type-Options`, `X-Frame-Options`, and `X-XSS-Protection "1; mode=block"`; no `Content-Security-Policy` or `Referrer-Policy`.
- Impact: No CSP means injected/3rd-party scripts are unrestricted; missing Referrer-Policy leaks full URLs to CDNs; `X-XSS-Protection` is deprecated and ignored/harmful in modern browsers. Since translations.js writes hardcoded markup via `innerHTML`, a CSP is cheap defense in depth.
- Fix: Add `Header set Referrer-Policy "strict-origin-when-cross-origin"` and a `Content-Security-Policy` allowing self plus the Google Fonts and cdnjs origins; drop `X-XSS-Protection` or set it to `0`.

### [M3] Soft-404: ErrorDocument 404 serves the homepage
- Where: .htaccess:34 (`ErrorDocument 404 /index.html`)
- Evidence: Any non-existent URL returns the full homepage with a 200-style experience instead of a real 404.
- Impact: Search engines see duplicate/soft-404 content for broken URLs, hurting SEO and indexing; users get no signal the page is missing.
- Fix: Create a small `404.html` that returns a proper 404 status and point `ErrorDocument 404 /404.html`.

### [M4] No .gitignore and core.fileMode noise pollutes git status
- Where: project root (no .gitignore); `git config core.fileMode` = true
- Evidence: `git status --short` shows all 13 tracked files as modified solely due to 777/executable mode changes; new `.claude/` is untracked with no ignore rule.
- Impact: Every commit risks capturing meaningless mode changes; real content diffs are buried in noise; editor/OS junk and `.claude/` can be committed accidentally.
- Fix: `git -C "<repo>" config core.fileMode false` to ignore mode-only changes, and add a `.gitignore` covering `.claude/`, `.DS_Store`, editor folders. (Audit makes no repo changes itself.)

### [M5] Hardcoded preloader delay and copyright year
- Where: js/main.js:5-9 (`setTimeout(..., 2000)`); index.html:514 (`© 2026 ... جميع الحقوق محفوظة`)
- Evidence: Content stays hidden (`body overflow:hidden`) for a fixed 2s after `load`; footer year is a literal `2026`.
- Impact: The 2s gate adds perceived latency for all users even when assets are already cached; the static year will silently go stale and require a manual edit each January.
- Fix: Reduce/remove the artificial delay (hide preloader on `load` directly), and render the year dynamically (e.g. `new Date().getFullYear()` injected into the copyright span).

## Low

### [L1] Unreferenced 244 KB logo.png shipped as dead weight
- Where: assets/logo.png (244 KB); index.html uses assets/unnamed-removebg-preview.png (82 KB) for nav/footer logos
- Evidence: `grep logo.png index.html` returns nothing; logo.png is the largest asset by far.
- Impact: 244 KB of dead bytes deployed and version-controlled for no purpose.
- Fix: Remove assets/logo.png, or reference it intentionally if it is the canonical brand asset.

### [L2] Images lack loading="lazy" and intrinsic dimensions
- Where: index.html:40, 277-333, 463, 475 (9 `<img>` tags)
- Evidence: No `loading` or `width`/`height` attributes on any image.
- Impact: All product images load eagerly even when below the fold; missing dimensions can cause layout shift (CLS).
- Fix: Add `loading="lazy"` to below-the-fold product images and explicit `width`/`height` to reserve space.

### [L3] Poorly named production assets
- Where: assets/unnamed.jpg, assets/unnamed-removebg-preview.png
- Evidence: Generic download-default filenames used directly in production markup (logo and contact image).
- Impact: Unclear intent, hard to maintain, weak for SEO/asset management.
- Fix: Rename to descriptive names (e.g. logo-transparent.png, contact-hero.jpg) and update the references.

### [L4] Nav links duplicated between desktop and mobile menus; README is stale
- Where: index.html:47-54 (desktop nav) vs 67-74 (mobile menu); README.md:9-13, 32-41
- Evidence: Six nav items are maintained in two places; README's file tree omits the `assets/` folder and Step 4 documents a `contactForm` that no longer exists in the markup.
- Impact: Drift risk (links can diverge between desktop/mobile); README can mislead a deployer into skipping assets or expecting a form that is not there.
- Fix: Acceptable for a static site, but consider templating the nav; update README to list `assets/` in the deploy tree and reconcile the contact-form instructions with the current markup.

## Optimizations
- The scroll listener (js/main.js:20-29) fires `navbar.classList.toggle`, a `getElementById('backToTop')` lookup, and `updateActiveNav()` (which queries all sections) on every scroll event with no throttle/rAF. Wrap the work in `requestAnimationFrame` with a dirty flag, and consider an IntersectionObserver for active-nav detection (the codebase already uses observers for animations/counters).
- `updateActiveNav` re-runs `document.querySelectorAll('section[id]')` and `.nav-link` on every scroll; cache these node lists once.
- Total raster assets are ~600 KB. Convert PNG/JPG products to WebP/AVIF for a large transfer-size win; the .htaccess cache headers already favor long-lived images.
- Both translations.js and main.js are unminified plain files; for a manual-deploy site this is fine, but a one-line minify step before upload would cut ~25 KB of JS.
